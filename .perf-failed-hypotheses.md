# Failed Hypotheses Log

Institutional memory for performance experiments that did not yield results.
Read this before repeating performance investigations.

## 2026-07-14 Hypothesis: Full-task terminal scans caused the WorkflowRuntime scaling collapse
- **Observation:** 128-node WorkflowRuntime benchmarks took about 30 ms before the checkpoint audit.
- **Attempted:** Removed only the unintended checkpoint calls from generic Run/Task notification paths, leaving terminal-state scans unchanged, then rebuilt with GCC 15, `-O3 -DNDEBUG -march=native`, pinned to NUMA node 0, and reran representative workloads.
- **Result:** Final repeated measurements put the 128-node linear scenario at a 3.05 ms median and the fan-out scenario at 2.92 ms; the unchanged terminal scan remained in the path. The linear sample had higher noise, while fan-out had 3.02% CV.
- **Elimination signal:** The symptom largely disappeared without changing the proposed mechanism, and scaling returned close to linear over 8, 32, and 128 nodes.
- **Lesson:** A visible O(N) scan is not necessarily the dominant cost; first account for nested full-state copies and persistence operations around it.

## 2026-07-14 Hypothesis: Conditional-edge scanning caused the WorkflowRuntime scaling collapse
- **Observation:** `conditions_pass()` scans plan edges, so linear and fan-out plans appeared capable of producing quadratic work.
- **Attempted:** Kept edge evaluation unchanged while removing only unintended state-notification checkpoints, then compared linear and fan-out execution at 8, 32, and 128 nodes.
- **Result:** Both graph shapes converged to similar 128-node medians (3.05 ms linear, 2.92 ms fan-out) and no longer showed the prior approximately 30 ms collapse.
- **Elimination signal:** The original symptom disappeared while the edge-scan implementation was unchanged.
- **Lesson:** Retain edge indexing as a future scalability candidate, but do not treat it as the root cause of the observed regression without larger-graph evidence.
